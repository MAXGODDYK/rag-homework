# HW2: Semantic retrieval для асистента особистого планування

HW2 продовжує підготовлену в HW1 knowledge base і додає базовий semantic retrieval layer:

```text
chunks.jsonl
    → multilingual embeddings
    → L2 normalization
    → FAISS IndexFlatIP
    → top-k semantic search
    → chunks із metadata
```

## Semantic retrieval

- модель: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`;
- мови: українські chunks, українські та англійські queries;
- розмірність embedding: **384**;
- vector storage: локальний **FAISS**;
- індекс: `IndexFlatIP`;
- метрика: cosine similarity завдяки L2-нормалізації;
- стандартний `top-k`: **3**.

Мультимовну модель обрано через українську мову бази знань. Chunks і query завжди кодуються тією самою моделлю.

## Предметна область

**Student Personal Planning** — особисте планування навчання та повсякденних справ студентів.

Мета chatbot — допомагати студентам:

- планувати підготовку до іспитів;
- складати реалістичний режим дня;
- визначати пріоритети;
- розподіляти час між навчанням, відпочинком і непередбаченими справами;
- підтримувати продуктивність без перевантаження.

Мова бази знань і відповідей chatbot: **українська**.

## Встановлення та запуск

Команди PowerShell із каталогу `HW_2`:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\scripts\prepare_knowledge_base.py
.\.venv\Scripts\python.exe .\scripts\build_index.py
.\.venv\Scripts\python.exe .\scripts\retrieval.py "Як скласти план підготовки до іспиту?" --top-k 3
```

Перший запуск Sentence Transformers завантажує публічну модель із Hugging Face. Попередження про відсутній `HF_TOKEN` не заважає роботі моделі.

Якщо Windows PowerShell некоректно показує українські символи:

```powershell
chcp 65001
$env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
```

`prepare_knowledge_base.py` повторно готує 3 документи та 25 chunks. `build_index.py` перевіряє chunks, створює embeddings, нормалізує їх і зберігає FAISS index. `retrieval.py` приймає query і повертає top-k результатів із `chunk_id`, score, document, source, title, section та text preview.

## Артефакти індексу

| Файл | Призначення |
|---|---|
| `index/embeddings.npy` | Матриця 25 нормалізованих векторів `float32` форми `(25, 384)` |
| `index/faiss.index` | Серіалізований `IndexFlatIP` із 25 векторами |
| `index/manifest.json` | Модель, метрика, розмірність і порядок усіх `chunk_id` |

FAISS не зберігає тексти та metadata. Позиція вектора зіставляється з відповідним рядком `chunks.jsonl` через порядок `chunk_ids` у manifest. Індекс записується через `faiss.serialize_index()` і Python `Path.write_bytes()`, оскільки стандартний файловий API FAISS у Windows не підтримує шлях проєкту з кирилицею.

## Pipeline обробки

```text
Локальні HTML
    → видалення службових тегів і HTML-коментарів
    → вибір контейнера основної статті
    → збереження заголовків, абзаців і списків
    → нормалізація пробілів
    → формування смислових розділів
    → normalized_documents.jsonl
    → поділ за абзацами та реченнями
    → section-aware chunking 800/150
    → перевірка ID, metadata та довжини
    → chunks.jsonl
```

Під час очищення видаляються `script`, `style`, `nav`, `header`, `footer`, `aside`, `form`, `svg`, `noscript` та HTML-коментарі. Для джерел використовуються окремі контейнери статей:

- МОН — `div.editor-content`;
- ЗУНУ — `div#article div.timg`, до блока «Інформація про»;
- УГІ — `section.article-intro div.wprt-container`, до форми «Залишити відповідь».

Текст меню, контактів, форм, footer, copyright і блоків схожих публікацій до результату не потрапляє.

## Формат даних

Кожний рядок `normalized_documents.jsonl` є окремим JSON-об'єктом із полями:

- `document_id`, `source_file`, `source_url`, `title`;
- `text` і масив `sections`;
- `language`, `domain`, `document_type`, `accessed_at`.

Кожний рядок `chunks.jsonl` містить:

- `chunk_id`, `document_id`, `source_file`, `source_url`;
- `chunk_index`, `text`, `metadata`.

Структура `metadata`:

```json
{
  "title": "Назва документа",
  "section": "Назва одного або кількох розділів",
  "language": "uk",
  "domain": "student_personal_planning",
  "document_type": "web_article",
  "source_type": "html",
  "accessed_at": "2026-07-20"
}
```

Формат ID: `document_id_chunk_NNN`. Нумерація починається з 1 окремо для кожного документа.

## Стратегія chunking

- цільовий розмір: **800 символів**;
- overlap: щонайменше **150 символів**, набраних цілими реченнями;
- допустима підсумкова довжина: **500–1000 символів**;
- межі chunk обираються між реченнями або абзацами;
- слова й речення не обриваються;
- у текст додаються назва документа та назви охоплених розділів.

У поточних даних overlap надав достатньо контексту останнім фрагментам, тому всі chunks одразу потрапили в допустимий діапазон і додаткове об'єднання короткого залишку не знадобилося.

## Результати semantic retrieval

Перевірено 8 українських queries, для кожного збережено top-3 результати та ручну оцінку релевантності в `outputs/retrieval_examples.md`.

| Оцінка | Кількість queries |
|---|---:|
| `relevant` | 5 |
| `partially relevant` | 3 |
| `not relevant` | 0 |

Найвищий score — `0.8649` для запиту «Як правильно організувати режим дня студента?». Додатковий англомовний query про баланс навчання, сну та відпочинку повернув три релевантні українські chunks зі scores `0.7397`, `0.6855` і `0.6470`, що підтверджує cross-lingual retrieval.

## Обмеження baseline

- FAISS завжди повертає top-k найближчих chunks, навіть якщо query поза предметною областю;
- score threshold і fallback поки не реалізовані;
- metadata filtering, hybrid search і reranking не використовуються;
- широке або складене питання може вимагати інформацію з кількох chunks;
- semantic similarity не гарантує, що кожний результат прямо відповідає на питання.

## Приклади chunks

### Підготовка до іспиту

`exam_time_planning_chunk_001`, 777 символів, розділи «Вступ / Порада №1»:

```text
Назва: Як розпланувати час, готуючись до іспиту?
Розділ: Вступ / Порада №1: Знайдіть свій ідеальний час для навчання

Планування часу, або ж тайм-менеджмент, допомагає перерозподілити свої ресурси та навантаження так, щоб і завдання виконати ефективно, і не виснажитися.

Засновник компанії «GreenPal» Брайан Клейтон також зауважує, що застосування тайм-менеджменту не лише сприяє робити всі завдання вчасно чи швидко, а також у правильний для вас час. Тайм-менеджмент зекономить зусилля. Ба більше – ефективне планування часу допоможе досягти бажаного результату. Спільно зі студією онлайн-освіти EdEra ми підготували дієві лайфхаки, щоб ви встигли все розпланувати правильно!

Згідно з теорією хронобіології на рівні ДНК ми маємо ідеальний біологічний час для продуктивності.
```

### Режим дня студента

`student_daily_routine_chunk_001`, 775 символів, розділи «КРОК 1 / КРОК 2 / КРОК 3»:

```text
Назва: Основні кроки ефективної організації режиму дня студента
Розділ: КРОК 1 / КРОК 2 / КРОК 3

Визначте свою мету в житті на найближчі роки. Візьміть ручку і папір і напишіть такі категорії: навчання, побут, взаємовідношення з іншими, риси характеру. Біля кожної з них напишіть те, що вам хотілося мати, змінити чи покращити в майбутньому. Виберіть 5-6 найосновніших цілей. Складіть план роботи реалізації виділених перспектив на цей місяць, тиждень і конкретний план на наступний день.

Проаналізуйте свій звичний розпорядок дня. Впродовж кількох днів заповнюйте шаблон режиму дня, аби зрозуміти, на що йде основна маса вашого часу.

Прийшовши із занять, розподіліть свої справи в порядку їх важливості. Для цього поділіть справи на ті, які необхідно зробити невідкладно.
```
