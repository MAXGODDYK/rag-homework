# HW4: розвиток grounded prompt

## Версія 1 — простий context prompt

```text
Відповідай на питання за наведеним контекстом.

Контекст:
{context}

Питання:
{question}
```

Проблема цієї версії — відсутній явний fallback, немає контракту
citations і не визначено, що текст chunks є недовіреними даними.
Модель може доповнити відповідь власними знаннями або виконати
інструкцію, випадково знайдену в джерелі.

## Версія 2 — grounding, fallback і citations

```text
Відповідай тільки за контекстом.
Якщо інформації недостатньо, поверни fallback.
Для звичайної відповіді наведи chunk_id джерел.
Не використовуй chunk_id, яких немає у списку дозволених.
```

Ця версія задає правильну поведінку для питання без відповіді,
але формат ще може змінюватися між запусками. Простого текстового
списку citations недостатньо для надійної автоматичної перевірки.

## Версія 3 — фінальний multilingual JSON contract

Фінальний prompt зберігається у
`prompts/grounded_qa_prompt.txt`. Він:

- передає кожний chunk в окремих межах `[CONTEXT n]`;
- вказує `chunk_id`, `source_file`, `section` і повний текст;
- трактує chunks як недовірені дані;
- забороняє факти, висновки та рекомендації поза контекстом;
- вимагає мову питання;
- задає точну fallback-фразу;
- дозволяє citations тільки з top-3;
- вимагає один JSON object без Markdown.

Зовнішня Python-перевірка не довіряє JSON моделі: вона перевіряє
точний набір полів, типи, непорожню відповідь, citations як
підмножину top-3 і порожні citations для fallback. Після першої
помилки виконується одна repair-спроба; після другої повертається
безпечний deterministic fallback.

## Порівняння на трьох типах питань

| Випадок | Версія 1 | Версія 2 | Версія 3 |
|---|---|---|---|
| Релевантне: план підготовки | Може відповісти правильно, але без перевірних джерел | Є fallback і citations, формат нестабільний | JSON валідовано; фактичний local run повернув grounded відповідь і дозволені citations |
| Без відповіді: столиця Франції | Модель може використати загальні знання | Prompt просить fallback, але retrieval усе одно запускає LLM | Raw BGE `0.000017` нижче `0.005`, тому LLM не викликається |
| Слабкий retrieval: зміна університету | Високий ризик загальної персональної поради | LLM має самостійно розпізнати нестачу контексту | Raw BGE `0.000497` нижче порога; повернено deterministic fallback |

## Фактичний висновок

Версія 3 на восьми обов’язкових питаннях дала 8/8 очікуваних
fallback/non-fallback рішень і не пропустила жодної citation поза
retrieved top-3. Ручна оцінка: 6 відповідей `relevant`, 2 —
`partially relevant`, 0 — `not relevant`.

Водночас JSON/citation validation не доводить повну
groundedness. У відповіді про пріоритети модель сформулювала
детальніше правило, ніж містять chunks, а відповідь про перерви
має мовну похибку. Ці приклади показують, навіщо поряд із
автоматичним контрактом потрібна ручна оцінка або окремий
entailment/faithfulness evaluator.
